# AGENTS.md

Portable instructions for any coding agent (Claude Code, Codex, Cursor, Copilot, Aider…) working in this repo.
They replace the two older rulebooks, which are kept unchanged for the record in
`docs/legacy/flamescope-v1/AGENTS.md` and `docs/legacy/hearth/CLAUDE.md` and are no longer in force.

## Project

FlameScope, by Team Polaris, for NASA Space Apps 2026: **Flame in Freefall**. A Next.js app that summarises,
ranks and interprets NASA microgravity combustion experiments for crewed habitats, guided by the assistant
**VESTA**. It holds two kinds of evidence and never pools them (ADR-017):

- **Gas and droplet flames:** NASA PSI investigations ACME, CFI and SPICE, cleaned into `data/processed/`.
- **Solid materials:** NASA's BASS-II report NASA/TM-20210011385 (acrylic sheets, SIBAL fabric, Nomex),
  transcribed into `data/evidence/` and answered by the rule-based engine in `lib/evidence/`.

## Commands

| Task | Command |
|---|---|
| Install | `npm ci` |
| Run | `npm run dev` → http://localhost:3000 |
| Types | `npx tsc --noEmit` |
| Lint | `npm run lint` |
| Test | `npm test` (must stay green) |
| Evidence evaluation | `npm run evaluate` (must stay 20/20) |
| Build | `npm run build` (stop any dev server first: both write to `.next`) |
| Blueprint | `npm run blueprint`, then `npm run blueprint:reviewed` only after re-reading the stories |

is made by accident. Don't add a dependency without an ADR in `docs/planning/decisions.md`.

## Layout and boundaries

```text

components/        React. Renders what the server computed; computes no claim.
lib/               data access, tested formulas, analysis, safety rules. lib/brand.ts is the only place product identity lives.
lib/vesta/         the only model code: agent loop, engine router, providers, tools, Offline mode, grounding.
lib/evidence/      the solid-material engine. Deterministic: no fetch, no model, no process.env, no Math.random,
                   no import from outside the folder. Only files.mjs reads the disk. Enforced by tests/evidence/boundary.test.mjs.
lib/burn.ts        the typed front door to that engine for the server. lib/evidence/client/ is its browser side.
data/processed/    generated by scripts/ingest/ingest.py from Pseudo_DataKeep/. Don't edit by hand.
data/evidence/     committed source rows and their provenance JSON. psi-*.csv are NASA's bytes: .gitattributes keeps them exact.
Pseudo_DataKeep/   raw NASA files. Read-only.
scripts/blueprint/ generates public/blueprint.html. Never edit that file by hand.
tests/             vitest. tests/evidence/ holds the engine's suites.
docs/planning/     vision, requirements, architecture, data model, ADRs.
docs/integration/  how the two projects were unified, and the QA record.
docs/legacy/       both projects' earlier root docs, unchanged.
```

## Non-negotiable rules

1. **Every number has a source.** It comes from a data row or a tested formula. New data needs a provenance
   entry (report, table, page, method, verification status, licence) and a test that reproduces two published values.
2. **Missing stays missing.** Use `null`. Never write 0, never interpolate between recorded values, never
   extrapolate beyond them, and never swap a condition the user gave for a default.
3. **No safety rating.** Never output "safe", "certified" or a score presented as NASA's. Heuristic scores are
   labelled as FlameScope heuristics. A scenario no test recorded is "no data", with sourced gaps.
4. **Solid answers are computed, never generated.** `lib/evidence/` produces them by fixed rules. VESTA's
   `will_it_burn` tool passes that answer on and adds no number; a model may quote it, not restate it as a
   rating or stretch it to conditions its rows did not record.
5. **VESTA never states a number it did not get from a tool result or the user's message.** The grounding check
   enforces this for every engine. Don't weaken it.
6. **The two evidence sets are never pooled.** No BASS-II row goes into `data/processed/`; no gas or droplet
   count answers a question about a solid material.
7. **Simulations are labelled DEMO** and never mixed with NASA data.
8. **The app must never break because a key is missing, a limit is hit or a model service is down.** Offline
   mode always answers.
9. **Secrets stay on the server.** Keys come from the environment only. `.env.example` lists names only. Never
   print, log or commit a key. `FREELLMAPI_*` and `VESTA_EVAL_TOKEN` are for local use only.
10. **User text is untrusted data.** Never interpolate it into instructions, HTML or shell.
11. **Don't push, deploy or change hosting settings unless a person asks for exactly that.**

## Style

- TypeScript strict in the app; the evidence engine is plain ES modules and stays that way unless an ADR says otherwise.
- Match the surrounding code. Add or change a behaviour → add or change a test.
- Add or remove a page, API route, VESTA tool, engine, top-level `lib/*.ts`, shell component or dependency →
  add or remove its story in `scripts/blueprint/stories.ts` and rebuild the Blueprint. Never type a number into
  a story: use `{{factName}}`. When a watched pipeline file changes, re-read its section before marking it reviewed.
- Changed a boundary or a dependency → add an ADR. Changed the Will it burn? page → update its row and the change
  log in `docs/planning/features.md`.
- Product name, links, export names, storage keys and the logo come from `lib/brand.ts`. Don't write them elsewhere.
- Commit messages: imperative, and say why. Don't commit or push unless asked.
- Log any AI assistance in `docs/AI_USE.md` (tool, what it did, what a human verified).

## Definition of done

`npx tsc --noEmit` is clean, `npm run lint` is clean, `npm test` is green, `npm run evaluate` is 20/20,
`npm run build` succeeds, the docs are updated, and the AI use is logged. Report the actual numbers.
